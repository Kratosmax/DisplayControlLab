# 实机能力验证与适配包边界

此页为早期实机审计，界面/写入开放状态以当前源码与 [两屏适配验证](MONITOR_ADAPTER_VALIDATION.md) 为准；不要把下文历史“尚未实现”描述当作当前产品状态。

日期：2026-10-11。这是已批准设计进入实现后的第一批功能验证，不表示九页新界面已经实现。测试全程后台运行，没有鼠标、键盘或窗口激活操作。

## 实际设备和通道

| 设备 | 标准 Windows DDC | AMD 原始 DDC | 验证范围 |
|---|---|---|---|
| AOC Q27G4ZMN / AOC 0xB411 | 14 个内置项目，两轮成功 | F8E1 私有 11 项，两轮成功 | 当前 DisplayPort、AMD 显卡、系统 SDR |
| MSI G273Q / MSI 0x3CA8 | 相同 14 个内置项目，两轮成功 | 本次返回全 FF，响应无效 | 当前 DisplayPort、AMD 显卡、系统 SDR |

实际经 Controller/适配包路由读取：标准目录 56/56 次成功；AOC 私有包和 MSI 标准测试包合计 36/36 次成功。MSI 测试包只用于验证相同文件格式和设备隔离，不分发给普通用户；标准能力不需要每个型号单独安装一份包。

第一次 MSI 常规扫描亮度失败，后续两轮独立读取成功，均保留证据；不能把一次失败固定解释为不支持。原始通道失败与标准通道成功同时成立，不能将某种通信后端在 AOC 的成功推广到其他设备。

## 内置标准能力

亮度、对比度、红/绿/蓝增益、色温预设、音量、静音、输入源、电源状态、画面预设、OSD 状态、OSD 语言、MCCS 版本，共 14 项。每个项目仍以当前设备实际读取和条件为准，不因为列在目录就显示成功。

输入源、色温和其他枚举目前保留原始值，不在缺少选项验证时开放写入；电源和输入切换本轮没有执行。数字项目继续按实际最大值检查，枚举和版本状态不使用这个规则。

修正了两个旧假设：MSI 输入源返回 current=15、maximum=3，不能据此拒绝读取；AOC 原始 MCCS 返回 current=514、maximum=255，也不是非法滑块值。最大字段的含义必须随功能类型解释。

## 仍待适配的功能

官方软件存在 E2A0/18 区域调光、E2A0/20 色域、E2A0/40 Adaptive-Sync 的候选定义。本次发送已知格式的 GET，各两次均返回 result=1 的错误响应，未取得有效值。数据不显示成 0 或关闭。

这些失败只覆盖当前格式/通道，不能据此排除设备支持。对应菜单留在目录，但不开放写入；后续查该型号实际使用的私有路径。游戏模式的标准 DC 命令有官方软件线索，但 OSD“标准”和官方枚举“自定义”名称存在差别，不直接套模式标签。图像比例以及其他未显示菜单的编码仍待确认。

## 适配包合理性与实现状态

1. 标准功能内置，共享目录随实际能力判断可用性，不按型号复制包。
2. 型号私有包描述差异、分组、类型、条件和报文。当前 AOC 示例已扩展为 11 项，仅六项包含写入入口（其中五项按实测值限制）。
3. 已添加 valueType/group/verification、allowedWriteValues、writeWhenWindowsHdr。读取选项和允许写入选项分开，未测 HDR 上下文不继承 SDR 验证。
4. verification 是包作者的声明，不是可信认证或安全权限；本机证据另存。不能仅修改此字段使未知写入成为已验证。
5. 专用驱动仍由代码插件处理；不同显卡/通道不能强制走 AMD。当前 v1 原始协议解释器仍只覆盖已知 DDC 帧，复杂结构使用插件。
6. 当前单包绑定、数值式插件结果仍需按已批准规格替换为多提供者、有类型能力、依赖诊断和共享工作流。这些产品重构没有因为本次实机成功而算完成。

建议以上述分层扩展设备支持。边界：相同协议家族不代表型号、固件、显卡和接口全部兼容；封闭 SDK 也必须允许第三方调用。需按设备和条件保留验证矩阵，不能直接将 AOC 私有请求发往 MSI。

## 重跑与证据

所有设备身份、完整请求/回包、返回码、参数快照和失败保存在项目 `temp/validation/capability-audit`，不进产品包：

- live-read-audit.json：86 次原始 GET，包含 MSI 全 FF 无效响应。
- e2a0-read-audit.json：六次错误响应。
- msi-windows-ddc.json：首次 Windows 常规扫描。
- standard-routing-results.json：两设备标准目录 56 次成功。
- routed-read-results.json：两种包实际路由 36 次成功。
- bounded-write-verification.json、numeric-private-write-verification.json：五项新增受控往返、恢复与参数快照。
- summary.json：独立检查每个响应、恢复结果后生成的摘要。

程序验证：`dotnet build DisplayControlLab.sln -c Release -m:1`；`tests/Platform/bin/Release/net8.0-windows/DisplayControl.Platform.Tests.exe . temp/validation/capability-audit/checked-platform-tests`。新增覆盖第二品牌匹配与绑定、枚举 maximum 语义、只读观察、部分值写入限制和 HDR 上下文限制。测试与硬件证据分别保存，模拟测试不当作硬件支持。

写入研究脚本只能在明确受控验证范围使用，不能当常驻控制接口；普通使用通过控制器及适配包。后续开发继续使用已批准九页设计，本轮技术预览仍是旧界面，不冒充设计成品。
