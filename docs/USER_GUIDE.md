# 使用教程

本地重构预览，非正式发布。Lite 需要 .NET 8 Desktop Runtime x64。

## 日常控制

1. 打开 DisplayControl.Controller.exe。启动优先读取全部显示器的常用值，再补充其他功能；选左侧显示器直接使用已有缓存。
2. 常用页调亮度/对比度：拖动松开后提交一次；数字框可按回车。设置页可切成手动应用，仅该模式显示应用按钮。只核查设置项及已声明联动项，不因一次调节全量扫描。
3. HDR 等预设点击选项；控件显示回读结果后才视为确认。紫色 HDR / 青色 SDR 徽标区分系统状态。旁边按钮可开关当前显示器的系统 HDR；接口不可用时禁用并提示。切换可能短暂黑屏，恢复后自动重读显示器预设/范围。外部切换也会被检测；重载不等于自动发送某个显示器预设。
4. 图像、游戏、声音和连接页展示同一份能力；“加入常用”收藏功能。“全部功能”同时展示待适配菜单。
5. 失败先看控件旁具体原因，或历史里的重新核查；研究则点“在读取器研究”。目标与设备回读不符会显示未确认，不连续重发。标准色温提供文字选项，厂商不同定义由适配包覆盖。
6. 不懂某项功能时，悬停名称旁的“? 说明”预览，或点击展开详细解释，再点“收起说明”。包括DCR、伽马、Overdrive、区域调光、色域等的作用与取舍；说明不会发送显示器指令。只读和HDR锁定时仍可查看，错误及适配限制继续直接显示。
7. 顶部可切换“详细视图 / 紧凑视图”，软件记住选择。紧凑视图为两列小控件：亮度/对比度各占半行，名称、滑块和数值同一行；预设用下拉框。点“?”查看帮助，点“⋯”展开来源、静态适配说明、收藏或研究操作。正常状态不重复显示数值，应用中、错误和锁定原因会直接展开；两种视图共用设置和帮助。

内置标准亮度遇Windows写入错误时先回读：已生效就确认；仅在原值/范围未变且设备与HDR复核通过后补发一次绝对值，最多两次SET。模式、身份、读数或范围变化则停止。该策略不用于私有协议、色温、输入源等其他设置。若设置未确认但当前值已读到，显示真实当前值并允许继续调节；当前值未知仍禁用并自动尝试单项重读。

## 安装适配支持

适配包 → 导入 JSON/ZIP → 检查型号、功能、依赖 → 安装 → 应用到当前设备。标准功能不依赖型号包。代码插件要明确同意运行当前内容，升级代码后需重新信任；它拥有当前用户权限。

本机 AOC Q27G4ZMN 可手动导入 examples/aoc-q27g4zmn/adapter.json，更新时替换已安装的同id包，再应用到主屏。1.5.0新增低输入延迟、准星开关及帧计数器关闭/右上/右下，仅在系统SDR且显示器HDR关闭时开放。左侧两档写入与回读编码不一致，暂不开放。支持取决于型号、固件、显卡和通道；示例不证明其他 AOC 设备可用。区域调光、色彩空间、Adaptive-Sync仍待协议；游戏模式、图像比例等仍只读，原因显示在功能旁。详细范围见OSD_CONTROL_VALIDATION.md。

多个互补包可同时使用。同功能来源冲突在功能控件选择；停用/卸载不删除实验、方案或历史。编辑用户副本得到新 id，不覆盖原包。

## 保存方案与恢复

“我的方案”勾选读取成功的可写项目，填写名字并保存。方案中的模式保存语义 id；game 在系统 HDR 的不同条件下可以解析成不同设备编码。

选择方案 → 预检差异 → 检查失败/可选项 → 应用。预检失败的必需项不发送；执行中一项失败就停止后续。编辑目标/必需项后需重新预检。

“操作历史”逐项显示发送和回读。恢复前重新读取；当前值已被其他软件或 OSD 改变时拒绝覆盖。只能恢复已确认且有原值的项目；无回读动作没有自动恢复。

## 查菜单切换

控制器的“在读取器研究”携带当前设备/功能打开读取器，再点“记录变化”，也可以独立打开读取器：

1. 实验记录 → 填写问题/采样范围 → 新建实验。
2. 菜单保持状态 A，点“开始采集此状态”。采两轮后自动暂停。
3. 暂停后操作显示器 OSD，输入新段名 B，再采两轮。
4. 切回 A，再采一段。选择任意两段比较；可另做无操作对照。
5. 名称可修订，过渡段可排除，轮次可移到相邻段修正边界。修改留记录，不改样本值。
6. 可连续采集，用底部“取消当前任务”暂停；取消中的部分轮保留但不作为完整稳定轮。
7. 关闭后从实验列表重开；导出 ZIP 包含原始样本，去标识分享会去掉设备路径、序列号和 EDID 原文。

比较同时考虑数值、范围、失败、提供者和 Windows HDR。没观察到变化只说明采集范围没看到；RGB/色温变化不会被自动叫作 HDR。扩展标准 GET 是可选高级诊断，较慢，也不能自动生成未知私有报文。

## 制作适配包

协议工作台 → 新建标准/私有协议 → 展开基本信息 → 填匹配与功能 → 填条件/稳定选项 id → 回放真实响应 → 主动测试读取 → 单独确认测试写入 → 导出/安装。

私有草稿默认没有有效指令，必须填入已知报文。测试证据单独保存；格式通过不代表设备兼容。代码插件用源码模板开发，编译成独立 exe，导入完整 ZIP 后信任并在控制页测试。JSON 高级视图与表单是同一模型。

两工具共享用户资料；单实例导航不会重新要求选择设备。后台资料同步不激活窗口。不会因目标离线而默选第一台。

## 单项读取失败

软件会有限重试GET，并在设置失败后自动只重读该项，不自动重发SET。持续失败会显示“上次确认值/当前尚未确认”、暂时禁用调节；点该项的“重试读取”即可核查，无需全局刷新。读取恢复后按实际值继续调节。HDR切换后的初读异常同样只重试失败项，不保留旧系统模式的选项。

## 显示器HDR与色温

当前AOC开启显示器HDR时，亮度、对比度、色温、RGB等冲突图像项禁用，状态未知也禁用。关闭“系统HDR”与关闭“显示器HDR预设”是不同操作。

通过软件从显示器HDR关闭状态进入时，先保存原色温和自定义RGB；退出确认后自动恢复。无记录或来源变化会明确提示，不猜原值。软件打开前/通过OSD已经进入HDR的情况，不保证有进入前记录；外部OSD退出不会自动触发恢复写入。恢复失败时停止后续项目，保留hdr-color-state证据。请先关闭旧两工具再开新版本，旧进程不具备这次保护。

## 系统HDR切换后的等待

切换后显示器可能短暂黑屏，软件显示“正在恢复显示状态”，暂时禁用调节。自动重新枚举、重读当前显示器，失败项延后重试；曾有失败时最后完整核查一次，以更新早期旧值。最多约20秒，恢复后自动加载模式选项。超时会说明尚未完全恢复，可刷新状态或单项重试；此过程不自动发送显示器设置。

## 软件更新与网络

“设置与帮助”中查看当前版本/通道，检查更新、查看已签名公告、稍后或跳过版本。启动检查可关闭。更新下载允许取消，100%仅表示包全部验证完成；实际替换由外部更新器执行。先退出另一工具；60秒仍有工具占用时不替换，不强制关闭。显示器操作进行中拒绝更新交接。软件更新保留用户适配包、方案和记录，不自动升级型号包。

网络线路按0–10优先级排序，0禁用；直连不能删除，允许禁用。GitHub前缀地址可带路径但不能带账号、查询和片段。HTTP网络代理仅支持无账号的http://主机:端口；留空不用代理。未保存编辑值可临时检查，保存后才用于后台。每条线路均验证签名、大小、哈希、版本、通道和ZIP结构。全部失败时可重试、修改线路或打开下载页面。

0.2.0无自动更新能力，手动安装/解压一次0.3.0；旧记录可只读导入。完整安装目录提供update-install.json身份与独立更新器，开发目录只给手动下载。更新失败保留日志和事务备份；下次启动在状态明确时恢复，回滚无法确认时不反复覆盖。
